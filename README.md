# dsh-session-rules · 会话守则

**简体中文** · [English](README.en.md)

给 DeepSeek Harness 加两份「守则」：**工作区守则**（一个目录一份，子目录可以沿用上层）和**会话守则**（只对这个会话生效）。写进去的文字会随该会话的系统提示词一起发给模型，用来放长期注意事项、编码规范、这一轮的临时约束。

所有开关**默认关闭**：只写内容不勾选，什么都不会发送。

## 安装

```bash
dsh plugin --profile desktop add github:lw0129a/dsh-session-rules
```

更新走同一个地址（仓库里带了构建好的 `dist/`，装完不用再编译）。本地开发时可以用绝对路径装这个目录。

装完重启 DeepSeek Harness。

## 怎么用

**工作区守则** — 侧边栏工作区行右侧 `⋯` → 「工作区守则」。

- 写这个目录下所有会话都该遵守的东西，比如「改完先跑 `npm test`」「只动和需求相关的文件」。
- 工作区有层级时（比如 `work` → `anjuyi` → `uni-platform-app`），子工作区只能**勾选是否沿用**上层的守则，改不了上层的内容。
- 新建的工作区还没有会话也能配置。

**会话守则** — 会话行右侧 `⋯` → 「会话守则」。

- 写只对这个会话生效的内容。
- 下面的「工作区守则」区按层列出，勾哪层就带上哪层（可多选；内容只读，要改去工作区守则面板）。

**生效**：点「保存」后从**下一轮**对话开始生效；清空内容再保存等于停用。

**优化描述**：把随手写的草稿交给当前会话正在用的模型整理成条目。结果不会直接覆盖原文，弹窗会并排显示「原描述 / 新描述」，点「替换原描述」才生效；模型不可用时只是报错，手写不受影响。

## 守则能写成什么样

编辑框按 Markdown 列表的方式工作（和 Typora 一样），内容按原样注入提示词，插件不改写、也不解析：

- 层级标记依次是 `-` → `1.` → `(1)` → `a.` → `(a)`，再深就重复 `(a)`；回车自动续一条同级别的条目，数字和字母都会自己加一（`a.` → `b.`）。
- 空条目上回车就退出列表；`Tab` 缩进一级（两个空格），`Shift+Tab` 退回一级；`⌘Z` / `Ctrl+Z` 撤销，`⇧⌘Z` / `Ctrl+Y` / `Ctrl+Shift+Z` 重做。
- 缩进、编号、`##` 小标题、表格都原样保留；条件分支就写成嵌套条目。
- 层级怎么理解由模型判断，插件只负责把它们按你写的顺序拼进提示词（多层工作区守则按“外层 → 内层”）。

## 会花多少 token

- 勾选之后，守则文字会出现在该会话**每一轮**的请求里；取消勾选就不再发送，内容仍留在本地。
- 工作区守则按层累加：勾三层就是三段文字一起进提示词。长守则同理。只在真正需要的会话里勾。

## 我的数据在哪

- 位置：`~/.dsh/plugin-data/dsh-session-rules/rules.json`（`DSH_HOME` 可覆盖）。
- 只属于这个插件；升级插件不会丢；换机器把该文件拷过去即可。
- 停用这个插件：入口消失、不再注入任何内容，文件原样保留。
- 删除工作区或会话：对应的守则会在下次读取时自动清掉。
- 卸载插件：文件会留在 `plugin-data/dsh-session-rules/`，不需要就手动删除。

## 边界

- 只读写上面那个文件；不碰 Harness 的 app 文件，不碰你项目里的任何文件。
- 不内置任何示例守则，不带任何用户内容，不上报任何数据。
- 唯一的联网行为是点「优化描述」时调用 Harness 自己配置的模型服务。
- 单条守则上限 100 K 字符。
- 工作区行 `⋯` 菜单在 DSH 里没有官方扩展槽位，那一项是靠 DOM 增强插进去的（复用内置菜单项的样式与键盘行为）；DSH 改侧栏结构时它可能失效。

macOS、Linux、Windows 都能用：守则按工作区的绝对路径保存，层级由路径关系推算，不依赖某个系统的写法。

装机细节、权限清单和开发说明见 [docs/DEVELOPING.md](docs/DEVELOPING.md)。
